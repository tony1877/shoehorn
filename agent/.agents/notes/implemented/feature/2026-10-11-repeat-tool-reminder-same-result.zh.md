# Agent Note：repeat-tool-reminder——相同结果检测与提醒后缀

Status: implemented

[English](2026-10-11-repeat-tool-reminder-same-result.md) | 中文

## 问题

一个本地 Qwen3.8 27B 会话在三项任务的编码测试上循环了约八分钟。任务 1 要求 10 个线程各自增 1000 次后得到 100000，而正确结果是 10000。模型第一次运行就打印了 10000，程序本来就是对的。在它唯一一次真正的推理中，模型算出 10 × 1000 = 100,000，随后认定是 shell 改写了输出。它写出内容完全相同的 `rtest1.py` … `rtestZ.py` 与 `rtest111.py` … `rtest999.py` 并逐个运行；每次 `pwsh` 调用都返回 `10000`，120 步中只有 4 步有推理。`repeat-tool-reminder` 从未触发：没有任何两次连续调用的参数完全相同，因为每次 `write` 都换了新文件名，每次运行也都指向那个文件。

## 决定

guard 新增一个可选的、以结果为键的第二检测器。当 `resultThresholds` 非空时，每个匹配 `resultInclude` 的被跟踪工具调用都会把 `(工具名, 结果内容块)` 记入该 agent 最近 `resultWindow` 次此类调用的历史。当相等条目的数量达到一个尚未针对该结果提醒过的阈值时，guard 送出提醒：第一个阈值是简短文本，要求模型停止尝试各种变体、重新审视自己的假设，包括任务中给出的预期；后续阈值是引用该结果的详细文本（截断到 `resultPreviewChars`）。键是完整的内容块，因此两张不同的图片互不相等。当精确重复链在同一次调用上也触发时，以它的提醒为准，因为它列出了重复的参数。用户提示会同时清空历史与链。

`reminderSuffix` 把部署指定的文本追加到每条提醒末尾。本地部署在这里设置 shoehorn 聊天模板的 `<|think_xhigh|>` 标记：模板会把该标记从渲染出的用户消息中删除，并把请求切换到 xhigh 推理强度，其系统指令要求模型验证关键假设。

base 组合为 `pwsh` 与 `bash` 开启相同结果检测，阈值 `[3, 5, 8]`，窗口 12 次调用。插件默认关闭它：对同一文件的每次正常 `edit` 都会返回相同的成功文本，比较所有工具的结果会在正常工作中频繁打扰。

## 考虑过的替代方案

**参数的模糊匹配**（比较前屏蔽数字或文件名）。它依赖每个工具参数的具体结构，而只要模型改动脚本内容，上面的循环仍会绕过它。无论调用如何变化，结果才是始终相等的信号。

**在服务端强制最少推理 token。** 它让每一步都增加延迟，包括很简单的步骤，并且不会告诉模型哪里出了错。若仅靠提醒无法恢复思考，它仍是一个独立的选项。

**只在连续调用之间统计相同结果。** 上面的循环交替调用 `write` 与 `pwsh`，连续规则需要与链相同的工具透明列表；而在该工具自己的最近调用上开窗口则不需要。

## 后果

相同的结果并不总是循环：持续通过的测试、或一直没有输出的命令也会收到提醒，可用 `resultInclude` 与 `resultThresholds` 加以限制。包含时间戳或临时路径的输出会绕过检测器。会被聊天模板解释的后缀可能改变提醒之前渲染的文本，因此每个会话会使缓存的提示前缀失效一次。

## 验证

`packages/guard/repeat-tool-reminder/tests/repeat-tool-reminder.spec.ts` 覆盖：默认关闭、所有调用都不同时的简短与详细提醒、窗口、窗口滑动时每个阈值只提醒一次、`resultInclude`、精确重复的优先级、用户提示的重置、后缀、结果截断、图片的完整内容块比较，以及新字段的快速失败校验。`src/index.ts` 保持 100% 的行、分支、函数与语句覆盖率。
