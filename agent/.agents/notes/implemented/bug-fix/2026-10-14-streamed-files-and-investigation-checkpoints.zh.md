# Agent Note: 流式文件预览与调查检查点

Status: implemented

[English](2026-10-14-streamed-files-and-investigation-checkpoints.md) | 中文

## Problem

文件参数以 assistant chunk 到达，但 Chat 工具行在完整工具调用时才开始。仅包含文件的 assistant 因此隐藏了数分钟可用的生成内容。精确重复检测器也无法发现命令与输出不断变化、却没有成功修改的调查。

## Decision

Chat 在生成期间发布文件工具参数块，并使用现有本地化代码组件显示解码内容。根 JSON 字符串读取器等待不完整的转义，仅保留最近的 16,384 个代码单元用于显示。执行仍由完整且已验证的工具调用负责；预览不创建新的 Session 事件，也无法写入文件。

repeat-tool-reminder 增加可选调查阈值与可配置重置工具。被跟踪调用增加每个 agent 的计数；成功重置工具与用户插入消息清零计数。精确调用及相同结果提醒优先。调查消息要求参考权威资料或运行断言，而不声称有效研究是失败。默认关闭此检测器。

## Alternatives considered

**生成期间写入部分文件**会失去原子验证并暴露错误或放弃的输出。只读预览保持文件系统执行器不变。

**在 UI 中分类类似分析的回答文本**无法可靠区分分析与用户要求的解释。推理策略负责区分 thinking；Chat 保留收到的块类型。

**否决长时间调查**会打断合理研究。建议计数提供检查点，不阻止调用，也不声称能检测语义进展。

## Consequences

预览有大小限制并在结束时消失，使实际工具行保持权威。大型文件在生成时显示尾部。调查计数衡量成功的重置工具，不判断任意 shell 操作的真实性或用途；部署选择适合其工具的阈值。

## Testing

Conversation assembler 回归在任何 tool/call 事件之前记录仅含文件的 partial。渲染器测试观察解码文本更新并在结束时消失。解码器覆盖转义、Unicode、嵌套字段及大小限制。Agent-loop 回归与现有重复检测套件一起固定建议文本及重置行为。
